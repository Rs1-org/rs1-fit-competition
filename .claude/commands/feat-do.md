# /feat-do — Execute Feature Plan

> **Agent-agnostic command.** Works with Claude Code, Codex, Cursor, or any agent that reads `.claude/commands/`.

---

## Purpose

Read the plan file generated by `/feat-plan` for the current feature and **implement it** — write all the code, in the correct order, following the project's exact folder structure, naming conventions, and RS1 rules.

This is the only command that writes source code.

---

## Usage

```
/feat-do "Club entity"
```

The name must match the plan file: `.claude/previews/plan-club-entity.md`

---

## Agent Instructions

### Step 1 — Load context
- Read `CLAUDE.md` — exact folder paths, naming conventions
- Read `.claude/docs/RS1_REQUIREMENTS.md` — every mandatory rule
- Read `.claude/docs/ENTITIES.md` — existing entities and relationships
- Read `.claude/docs/DECISIONS.md` — architectural decisions, do not contradict these
- Read the relevant member's `.claude/docs/features_<member>.md`
- Read the plan file: `.claude/previews/plan-<feature-name>.md`
- If no plan file exists → **stop**, tell user to run `/feat-plan "<feature>"` first

### Step 2 — Confirm before writing
Print a summary of what you are about to create:
```
Ready to implement: <feature name>
Files to create: X
Files to modify: X
Member: <name>
Estimated points: Xb

Proceed? (user must confirm)
```
Wait for user confirmation before writing any files.

### Step 3 — Implement in layer order
Always implement in this exact order — never skip ahead:

**1. Domain Layer first**
`Competition.Domain/Entities/`
- Create entity class inheriting `BaseEntity`
- No DataAnnotations for DB config
- Navigation properties defined but not configured here

**2. EF Configuration**
`Competition.Infrastructure/Data/AppDbContext.cs` → `OnModelCreating`
- Add `DbSet<Entity>` property
- Configure: PK, required fields, max lengths, FK relationships, indexes
- Add soft delete query filter: `.HasQueryFilter(e => e.DeletedAt == null)`

**3. DTOs**
- `<Entity>ListDto` — lightweight, for list views
- `<Entity>DetailsDto` — full, for detail views
- `Create<Entity>Dto` — accepted fields on create
- `Update<Entity>Dto` — accepted fields on update

**4. Commands + Validators**
`Competition.Application/Commands/<Entity>Commands/`
- `Create<Entity>Command.cs`
- `Create<Entity>CommandHandler.cs`
  - Must accept `CancellationToken cancellationToken`
  - Must pass token to every repository call
  - Must return DTO, never domain entity
- `Create<Entity>CommandValidator.cs`
  - Must have real validation rules — not empty
  - Use `.NotEmpty()`, `.MaximumLength()`, `.GreaterThan()` etc.
- Repeat for Update, Delete

**5. Queries**
`Competition.Application/Queries/<Entity>/`
- `GetAll<Entities>Query.cs` — must include PageNumber, PageSize + min 5 filter params
- `GetAll<Entities>QueryHandler.cs`
  - Must return `PagedResult<EntityListDto>` — never `IEnumerable<T>`
  - Must accept and pass `CancellationToken`
- `Get<Entity>ByIdQuery.cs` + handler returning `<Entity>DetailsDto`

**6. Repository (if needed)**
`Competition.Application/Interfaces/I<Entity>Repository.cs`
`Competition.Infrastructure/Repositories/<Entity>Repository.cs`
- All methods async
- All methods accept and pass `CancellationToken`
- Register in DI in `Program.cs` or equivalent

**7. Controller**
`Competition.Api/Controllers/<Entity>Controller.cs`
- Inject ONLY `IMediator` — zero direct service injection
- GET list → `_mediator.Send(new GetAll<Entities>Query(...))`
- GET by id → `_mediator.Send(new Get<Entity>ByIdQuery(id))`
- POST → `[Authorize]` + `_mediator.Send(new Create<Entity>Command(...))`
- PUT → `[Authorize]` + `_mediator.Send(new Update<Entity>Command(...))`
- DELETE → `[Authorize]` + `_mediator.Send(new Delete<Entity>Command(id))`
- Every action accepts `CancellationToken cancellationToken`
- Pass token to `_mediator.Send(command, cancellationToken)`

**8. Frontend**
`frontend/src/app/features/<entity>/`
- Feature module with lazy loading route registered in app routing
- `<entity>-list` component — Angular Material table
  - Min 5 filter params wired to query params
  - Pagination using Angular Material paginator
  - Uses Signal for state
- `<entity>-form` component — Angular reactive form
  - FE validation mirrors BE validation rules
  - Create and Edit modes in same component
- `<entity>.service.ts` — HTTP calls to API, exposes Signals
- Write routes protected by `admin-moderator.guard.ts`

**9. Tests**
`Competition.Tests/`
- Unit test: `Create<Entity>CommandHandlerTests.cs`
  - Test: valid command returns correct DTO
  - Test: invalid command throws validation error
- Integration test: `<Entity>ControllerTests.cs`
  - Test: GET list returns 200 + PagedResult
  - Test: POST with valid data returns 201

### Step 4 — Self-check before finishing
After writing all files, verify:
- [ ] Every handler has `CancellationToken` in signature AND in every repo call
- [ ] Every validator has real rules — not empty
- [ ] All list handlers return `PagedResult<T>`
- [ ] No domain entities returned from controllers or handlers
- [ ] All write endpoints have `[Authorize]`
- [ ] New entity inherits `BaseEntity`
- [ ] EF config has soft delete query filter
- [ ] Controller only uses `_mediator.Send()`
- [ ] Frontend lazy loaded route registered
- [ ] FE write routes use `admin-moderator.guard.ts`

If any check fails — fix it before finishing. Do not leave RS1 violations in the code.

### Step 5 — Report what was done
Print a summary:
```
✅ Implementation complete: <feature name>

Files created:
Backend:
  - Competition.Domain/Entities/<Entity>.cs
  - Competition.Application/Commands/<Entity>Commands/Create/...
  - Competition.Application/Commands/<Entity>Commands/Update/...
  - Competition.Application/Commands/<Entity>Commands/Delete/...
  - Competition.Application/Commands/<Entity>Commands/Validators/...
  - Competition.Application/Queries/<Entity>/GetAll/...
  - Competition.Application/Queries/<Entity>/GetById/...
  - Competition.Infrastructure/Repositories/<Entity>Repository.cs
  - Competition.Api/Controllers/<Entity>Controller.cs
Frontend:
  - frontend/src/app/features/<entity>/...
Tests:
  - Competition.Tests/<Entity>/...

RS1 self-check: all passed ✅

Next steps:
  1. Run /feat-check to verify RS1 compliance
  2. If clean → run /feat-update to log points
  3. git add . && git commit -m "feat: <feature name>"
```

---

## What /feat-do does NOT do
- Does not update `.claude/docs/` — that is `/feat-update`'s job
- Does not run `/feat-check` automatically — you run that manually
- Does not commit to Git — you do that after `/feat-check` passes
- Does not make architectural decisions — it follows `DECISIONS.md`

---

## Important Rules
- **Never contradict DECISIONS.md** — if a decision covers this feature, follow it
- **Never use DataAnnotations** for DB config — EF Fluent API only
- **Never return domain entities** — always map to DTOs
- **Never inject services into controllers** — only `IMediator`
- **Never hard delete** — always set `DeletedAt = DateTime.UtcNow`
- **Never leave empty validators** — real rules or don't create the file
