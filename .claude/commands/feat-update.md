# /feat-update — Apply Preview to Docs

> Run this after `/feat-check` confirms the branch is clean (Ready for /feat-update: YES).

---

## Purpose

Take the preview generated by `/feat-check` for the current branch and:
1. Sync `ENTITIES.md` with any new or modified entities found in the diff
2. Mark completed items in the member's feature doc
3. Add earned points to `POINTS_TRACKER.md`

This is the only command that writes to `.claude/docs/`. It never touches source files.

---

## Agent Instructions

### Step 1 — Load context
- Get current branch: `git branch --show-current`
- Read `.claude/previews/<branch-name>.md` — source of truth for this update
- Read `.claude/docs/ENTITIES.md`
- Read `.claude/docs/features_<member>.md`
- Read `.claude/docs/POINTS_TRACKER.md`

### Step 2 — Safety check
- If preview says `Ready for /feat-update: NO` → **stop immediately**, list the blockers, tell user to fix them first
- If no preview file exists for current branch → **stop**, tell user to run `/feat-check` first
- If `ENTITIES.md in sync: NO` in preview → **stop**, tell user to update `ENTITIES.md` first

### Step 3 — Sync ENTITIES.md
For every new entity detected in the preview's "Entity Sync Check" table:
- If status is `⚠️ NEEDS UPDATE`:
  - Read the actual entity file from the diff
  - Add a full entry to `ENTITIES.md` using this format:
    ```markdown
    ### <EntityName>
    \`\`\`
    <EntityName> {
      <field> : <type> (<constraints>)
      // Navigation
      <nav>   : <Type>
    }
    \`\`\`
    **Owner:** <member> | **Location:** `<path/to/Entity.cs>`
    ```
  - Update the entity count at the top of `ENTITIES.md`
- If an existing entity was modified (fields added/removed):
  - Update its entry in `ENTITIES.md` to reflect the change
- Do not reformat or rewrite other entries — only touch what changed

### Step 4 — Update feature doc
In `.claude/docs/features_<member>.md`:
- Find each checklist item marked ✅ in the preview's Implementation Checklist
- Change `- [ ]` to `- [x]` for those items only
- Do not touch items still ❌ in the preview
- Do not rewrite or reformat anything else

### Step 5 — Update POINTS_TRACKER.md
In `.claude/docs/POINTS_TRACKER.md`:
- Add the points earned this branch to the member's total in the scoreboard
- Update the member's Basic / Advanced / Total columns
- Update defense readiness status (🔴 / 🟡 / 🟢)
- Append one log row under the member's section:

```
| <date> | <branch name> | <feature name> | +Xb | <new total>b |
```

### Step 6 — Confirm
Print to console:
```
✅ ENTITIES.md — <X entities added/feat-updated, or "no changes">
✅ features_<member>.md — X items checked off
✅ POINTS_TRACKER.md — <member> +Xb → new total: Xb
Preview archived: .claude/previews/<branch-name>.md
```

---

## What /feat-update does NOT do
- Does not modify any source code
- Does not create Jira tasks
- Does not commit anything to Git
- Does not recalculate points from scratch — trusts the preview

---

## After /feat-update — commit the docs
```bash
git add .claude/docs/
git commit -m "docs: update after <feature> — +Xb <member>"
git push
```

---

## Usage

```
/feat-update
```
Always reads the preview for the current branch. No arguments needed.
